# Локальная проверка проекта

## 1. PostgreSQL

Создайте пустую базу `shop_portfolio`.

## 2. Backend

```bash
cd server
cp .env.example .env
npm install
npm run seed
npm start
```

Ожидаемый адрес API: `http://localhost:3500`.

Команда `npm run seed` создаёт тестовые товары и два аккаунта:

```text
Пользователь: demo.user@example.com / DemoUser123!
Администратор: demo.admin@example.com / DemoAdmin123!
```

## 3. Frontend

Во втором терминале:

```bash
cd client
cp .env.example .env
npm install
npm start
```

Откройте `http://localhost:3000`.

## 4. Пользовательский сценарий

- Войти под demo-пользователем.
- Проверить загрузку каталога.
- Добавить несколько товаров в корзину.
- Изменить количество и удалить товар.
- Создать бонусную карту и проверить, что отображаются её номер и баланс.
- Заполнить демонстрационные поля оплаты и оформить заказ.
- Открыть «Мои заказы» и проверить товары, сумму и статус.
- После изменения статуса администратором проверить новый статус в пользовательской части.
- Открыть «Мои чеки» после создания кассового чека.

## 5. Администратор / кассир

- Войти под demo-администратором.
- Проверить статистику и каталог.
- Открыть «Заказы» и изменить статус пользовательского заказа.
- Открыть вкладку «Касса».
- Отсканировать QR-код, содержащий числовой `product_id`.
- Изменить количество товара в кассовой корзине.
- Ввести номер бонусной карты и проверить баланс.
- Провести оплату.
- Проверить созданный чек, сумму, QR-код и начисленные баллы.
- Открыть «История чеков» и убедиться, что чек сохранился.
- Повторно проверить бонусную карту и убедиться, что баланс обновился.

## 6. Перед публикацией

- `.env` не должен попадать в Git.
- Не публиковать реальные пароли, токены, API-ключи, сертификаты и приватные ключи.
- Не добавлять `node_modules`.
- Не использовать реальные данные покупателей или компании в демо-базе и скриншотах.
- Выполнить `git status` и проверить состав файлов перед `git push`.
